Задайте `BASE_URL` как корневой HTTPS-адрес API без завершающего `/` и без `/v1`, а `API_KEY` передайте из хранилища секретов. OpenAI-совместимые SDK используют `${BASE_URL}/v1`, Anthropic-совместимые — `BASE_URL`.

Используйте точный публичный адрес нужного протокола: `${BASE_URL}/v1` для OpenAI-совместимого клиента; `BASE_URL` для Anthropic-совместимого. Не копируйте URL с ключом. Проверяйте сеть до генерации: каталог моделей не списывает кредиты.

## Сначала бесплатные проверки

1. Отправьте `GET /healthz` на `BASE_URL`. Ответ со статусом `ok` подтверждает доступность HTTP-сервиса. Доступ к конкретной модели проверяйте отдельно.
2. Проверьте HTTPS и правильный базовый адрес. Сам endpoint Messages — /v1/messages, хотя его base URL не содержит /v1.
3. Используйте [GET /v1/models](/ru/docs/api/models) с ключом, чтобы разделить сетевую, авторизационную и каталожную проблему.
4. Если curl работает, а клиент нет, сравните протокол, ID модели и источник credential с [совместимостью клиентов](/ru/docs/reference/clients).
5. Запустите [doctor](/ru/docs/troubleshooting/doctor) для бесплатных проверок клиента. Только явный --probe --yes допускает платный inference.

  | curl -q -H @- -i --max-time 10 "$BASE_URL/v1/models"

#python
~~~python
import os
import urllib.request


class NoRedirect(urllib.request.HTTPRedirectHandler):
    def redirect_request(self, request, fp, code, msg, headers, newurl):
        return None


opener = urllib.request.build_opener(NoRedirect)

base_url = os.environ["BASE_URL"]
key = os.environ["API_KEY"]

request = urllib.request.Request(
    base_url + "/healthz",
    headers={},
)

with opener.open(request, timeout=10) as response:
    print(response.status, response.headers.get("request-id"))
    print(response.read().decode("utf-8"))

request = urllib.request.Request(
    base_url + "/v1/models",
    headers={"Authorization": f"Bearer {key}"},
)

with opener.open(request, timeout=10) as response:
    print(response.status, response.headers.get("request-id"))
    print(response.read().decode("utf-8"))
~~~
#go
~~~go
package main

import (
	"fmt"
	"io"
	"net/http"
	"os"
	"time"
)

func main() {
	client := &http.Client{
		Timeout: 10 * time.Second,
		CheckRedirect: func(*http.Request, []*http.Request) error {
			return http.ErrUseLastResponse
		},
	}
	baseURL := os.Getenv("BASE_URL")
	if baseURL == "" {
		panic("BASE_URL is required")
	}
	key := os.Getenv("API_KEY")
	if key == "" {
		panic("API_KEY is required")
	}

	req, err := http.NewRequest("GET", baseURL+"/healthz", nil)
	if err != nil {
		panic(err)
	}

	response, err := client.Do(req)
	if err != nil {
		panic(err)
	}

	fmt.Println(response.StatusCode, response.Header.Get("request-id"))
	if _, err := io.Copy(os.Stdout, response.Body); err != nil {
		panic(err)
	}
	response.Body.Close()
	req, err = http.NewRequest("GET", baseURL+"/v1/models", nil)
	if err != nil {
		panic(err)
	}
	req.Header.Set("Authorization", "Bearer "+key)
	response, err = client.Do(req)
	if err != nil {
		panic(err)
	}

	fmt.Println(response.StatusCode, response.Header.Get("request-id"))
	if _, err := io.Copy(os.Stdout, response.Body); err != nil {
		panic(err)
	}
	response.Body.Close()
}
~~~
::

Первая команда должна вернуть HTTP 200 и `{"status":"ok"}`. Это подтверждает, что публичный сервис отвечает; проверка не подтверждает ключ, доступность модели или успешную генерацию. Вторая проверяет одновременно HTTPS, ключ и доступ к каталогу. HTTP 200 с `data` подтверждает, что сервис видит ключ; 401 или 403 направляет к [авторизации](/ru/docs/api/authentication), а 404 у конкретного ID модели — к [каталогу](/ru/docs/api/models). Ни одна из бесплатных проверок не гарантирует успех платного запроса к модели. Не записывайте команду с подставленным секретом в отчёт или скриншот.

| Наблюдение | Следующая проверка |
| --- | --- |
| Не определяется домен или соединение не устанавливается | Проверьте DNS, прокси и разрешение исходящего HTTPS до публичного hostname. Сохраните время и текст ошибки клиента без секретов. |
| Ошибка проверки TLS | Проверьте системное время и доверенное хранилище сертификатов устройства или прокси. Не отключайте проверку сертификата. |
| `/healthz` работает, но каталог отвечает 401/403 | Проверьте заголовок Bearer, срок действия ключа, организацию и права. Новая платная генерация не исправит авторизацию. |
| Каталог работает, но AI-клиент нет | Сравните base URL, протокол, канонический ID модели и способ передачи credential с [матрицей клиентов](/ru/docs/reference/clients). |
| API отвечает, но поток обрывается | Проверьте последнее SSE-событие и таймауты собственного клиента; сохраните тот же ключ идемпотентности до решения о повторе. |

При сбое DNS или TLS не отключайте проверку сертификата ради обхода. Передайте публичный hostname, время, безопасный код и ID запроса при наличии. Если запрос дошёл до API и получил ошибку, откройте [разбор ошибок](/ru/docs/troubleshooting/errors).
