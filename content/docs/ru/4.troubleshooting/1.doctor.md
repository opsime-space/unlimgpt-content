Запускайте `doctor`, если вход, API-ключ или уже настроенный клиент не работает. Для первого подключения начните с [быстрого старта](/ru/docs/getting-started/first-client). Обычный отчёт проверяет локальную конфигурацию, авторизацию и бесплатный каталог моделей; генерацию он не запускает.

~~~text
unlimgpt doctor --client codex
~~~

Замените `codex` на ID своего клиента из [матрицы совместимости](/ru/docs/reference/clients). Без `--client` проверка конкретного клиента будет пропущена. Отчёт печатает строки `PASS`, `WARN`, `FAIL` или `SKIP` с кодом проверки. Для автоматизации используйте `unlimgpt doctor --client codex --json`.

## Прочитайте результат

| Код | Что проверяется | Что сделать при проблеме |
| --- | --- | --- |
| `cli.runtime` | Версия CLI и ОС, на которых он запустился. | Сверьте установленную версию с [инструкцией установки](/ru/docs/cli/install). |
| `network.origin` | Формат настроенного HTTPS-адреса. Это не проверка доступности сервера по сети. | Укажите доверенный HTTPS-адрес при повторном входе. Для сетевого сбоя откройте [диагностику подключения](/ru/docs/troubleshooting/connection). |
| `cli.helper` | Наличие и исполняемость команды credential helper активного профиля CLI. Содержимое настройки клиента эта проверка не читает. | Переустановите CLI и повторите `configure`, чтобы клиент ссылался на установленный исполняемый файл. |
| `credential.store` | Наличие локального credential в системном хранилище. | `WARN` означает, что сохранённый credential не найден: войдите и настройте клиент. При `FAIL` разблокируйте или настройте системное хранилище; незашифрованного запасного способа нет. |
| `auth.identity` | Действительность авторизации самого CLI. | Повторите `unlimgpt login`. Это отдельная авторизация от API-ключа приложения. |
| `api.models` | Чтение бесплатного каталога API-ключом и наличие выбранного ID модели. | Выполните `unlimgpt models` и выберите ID из ответа. Для Codex сначала полностью закройте Codex Desktop; если каталог содержит `gpt-5.6-sol`, запустите `unlimgpt configure codex --model gpt-5.6-sol`. При ошибке доступа [проверьте ключ](/ru/docs/account/api-keys). |
| `client.compatibility` | Наличие ожидаемых файлов настройки клиента и поддержка режима CLI. Для клиента с ручной настройкой файловая проверка может отсутствовать. | `WARN` означает, что ожидаемый файл не найден; `FAIL` — неподдерживаемый режим или ошибка проверки. Сверьте [руководство клиента](/ru/docs/reference/clients) и повторите `configure`. Без `--client` здесь будет `SKIP`. |
| `inference.probe` | Один ограниченный запрос на генерацию только после явного согласия. | Без `--probe` здесь будет `SKIP`. При ошибке явной пробы проверьте [подключение](/ru/docs/troubleshooting/connection) и [кредиты](/ru/docs/account/credits-and-limits). |

`PASS` подтверждает только указанную проверку. `WARN` требует внимания, но не делает весь отчёт неуспешным; `FAIL` даёт ненулевой код завершения `7`. `SKIP` означает, что проверка не запрашивалась, а не что сервис исправен. Успешный `network.origin` не исключает сбой TLS или сети; `client.compatibility` не проверяет содержимое файла и реальное подключение клиента; `api.models` не подтверждает платную генерацию.

## Используйте JSON и платную пробу осознанно

~~~text
unlimgpt doctor --client codex --json
~~~

JSON содержит `schema_version`, `data.checks[]` с `code`, `status`, `message` и при наличии `remediation` или `evidence`. Смотрите `data.ok` для итога проверок и код завершения процесса; внешний `ok` сообщает, что CLI сформировал JSON-отчёт, и может быть `true` даже при `data.ok: false`. Перед передачей вывода поддержке просмотрите `evidence`: автоматическая маскировка секретов не заменяет проверку локальных путей и других метаданных. Обычно достаточно версии CLI, ОС, кодов и статусов проверок. Не отправляйте ключ, токен, prompt или response.

Только после бесплатной диагностики при необходимости запустите одну пробу. Она может списать кредиты:

~~~text
unlimgpt doctor --client codex --probe
~~~

В интерактивном терминале CLI запросит подтверждение. Для автоматического запуска добавьте `--yes` **только если** согласны на платную генерацию; без подтверждения проба получит `FAIL`. При повторе после неопределённого результата сначала проверьте [активность API](/ru/docs/account/usage), чтобы не запускать лишний запрос. Для отката настройки используйте [receipt и команду revert](/ru/docs/cli/configure) только для изменения, которым CLI ещё владеет.
