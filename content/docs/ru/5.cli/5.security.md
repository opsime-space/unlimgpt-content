Токен обновления OAuth для CLI и полные API-ключи находятся в системном хранилище. Файлы конфигурации содержат адреса, ID моделей и команды получения ключа, но не сам ключ. CLI не принимает секрет через аргумент `--api-key` и не предлагает хранить его открытым текстом при сбое системного хранилища. Настроенный AI-клиент всё равно получает ключ через поддерживаемую команду или окружение процесса; учитывайте его собственные правила хранения.

Перед использованием этих команд проверьте, что они есть в [справке установленного CLI](/ru/docs/cli/install).

## Проверьте границы хранения

Сверьте установленную версию через [локальную справку CLI](/ru/docs/cli/reference), затем просмотрите конфигурацию без секретов, созданную через [configure](/ru/docs/cli/configure). Не копируйте вывод команды получения ключа в запись терминала или обращение в поддержку: он предназначен для передачи ключа выбранному клиенту. Перед совместным использованием компьютера проверьте контроль доступа учётной записи ОС. Сессия браузера, авторизация CLI и API-ключ имеют отдельные сроки и способы отзыва.

Профиль CLI хранит ID выбранного ключа и модели, а полное значение остаётся в системном хранилище. Квитанция настройки фиксирует правку файла, выполненную CLI, для осторожного отката; храните её, не выгружая весь файл клиента. Ручной режим может передать ключ через буфер обмена или штатное секретное поле клиента — перед вставкой проверьте правила хранения самого клиента. Окружение дочернего процесса при безопасном запуске не следует выгружать в логи.

## Проверка и восстановление

В [Настройках → Аккаунт и безопасность](/ru/settings) отдельно просматривайте способы входа, сессии браузера, разрешения CLI и API-ключи. При потере компьютера с другого доверенного устройства отзовите его разрешение CLI и выделенные API-ключи. Одного завершения браузерной сессии недостаточно для отзыва ключа. Если на потерянном компьютере был открыт кабинет, завершите и его сессию браузера отдельным действием.

Если компьютер под вашим контролем, сначала составьте список выделенных ключей и клиентов, которые их используют. Для нужного ключа выпустите замену, бесплатно проверьте доступ через `GET /v1/models`, обновите все клиенты и затем отзовите старое значение. При потере устройства или уже раскрытом секрете быстро отзовите затронутый ключ из доверенного браузера и восстановите клиентов с новым. Не ждите выхода потерянного устройства в сеть.

~~~text
unlimgpt keys list
unlimgpt logout
~~~

Список ключей запрашивайте **до** выхода: `keys list` требует действующего разрешения CLI. На компьютере, который остаётся под вашим контролем, `logout` отзывает это разрешение и удаляет локальный токен, но не отзывает API-ключи. После выхода для команд управления ключами потребуется новый `unlimgpt login`; если устройство потеряно, работайте только из доверенного браузера. Отзовите конкретный неиспользуемый ключ через [руководство](/ru/docs/cli/keys) или [кабинет](/ru/api-keys). Убедитесь, что старый ключ неактивен, а замену бесплатно проверьте через [каталог моделей](/ru/docs/api/models). Сохраняйте квитанции настройки для безопасного отката; откат не затирает более поздние правки.

Если для сбоя настройки нужен `doctor`, просмотрите вывод перед отправкой: локальные пути тоже могут быть чувствительны. Передайте версию CLI, имя затронутого клиента и описание ошибки вместо всего окружения или значения ключа. См. [безопасность аккаунта](/ru/docs/account/security) и [приватность данных](/ru/docs/security/privacy).
