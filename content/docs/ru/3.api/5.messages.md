Задайте `BASE_URL` как корневой HTTPS-адрес API без завершающего `/` и без `/v1`, а `API_KEY` передайте из хранилища секретов. OpenAI-совместимые SDK используют `${BASE_URL}/v1`, Anthropic-совместимые — `BASE_URL`.

Выбирайте Messages для Anthropic-совместимого клиента. Базовый адрес — `BASE_URL`, без `/v1`. Нужны ключ организации, доступная модель и кредиты.

## Отправьте одно сообщение

::code-group
#curl
~~~bash
printf 'x-api-key: %s\n' "$API_KEY" \
  | curl -q -H @- -i "$BASE_URL/v1/messages" \
    -H "anthropic-version: 2023-06-01" \
    -H "Content-Type: application/json" \
    -d '{
  "model": "gpt-5.6-sol",
  "max_tokens": 64,
  "messages": [
    {
      "role": "user",
      "content": "Ответь одним коротким предложением."
    }
  ],
  "stream": false
}'
~~~

~~~python
import os

                }
            ],
            "stream": False,
        }
    ).encode("utf-8"),
)

with opener.open(request, timeout=120) as response:
    print(response.status, response.headers.get("request-id"))
~~~

~~~go
package main

import (
	"fmt"
	"io"
	"net/http"
	"os"
	"strings"
	"time"
)

func main() {
	client := &http.Client{
		Timeout: 120 * time.Second,
		CheckRedirect: func(*http.Request, []*http.Request) error {
			return http.ErrUseLastResponse
		},
	}
	baseURL := os.Getenv("BASE_URL")
	if baseURL == "" {
		panic("BASE_URL is required")
	}
	key := os.Getenv("API_KEY")
	if key == "" {
		panic("API_KEY is required")
	}

	req, err := http.NewRequest(
		"POST",
		baseURL+"/v1/messages",
		strings.NewReader(`{
  "model": "gpt-5.6-sol",
  "max_tokens": 64,
  "messages": [
    {
      "role": "user",
      "content": "Ответь одним коротким предложением."
    }
  ],
  "stream": false
}`),
	)
	if err != nil {
		panic(err)
	}
	req.Header.Set("x-api-key", key)
	req.Header.Set("anthropic-version", "2023-06-01")
	req.Header.Set("Content-Type", "application/json")

	response, err := client.Do(req)
	if err != nil {
		panic(err)
	}

	fmt.Println(response.StatusCode, response.Header.Get("request-id"))
	if _, err := io.Copy(os.Stdout, response.Body); err != nil {
		panic(err)
	}
	response.Body.Close()
}
~~~

HTTP 200 возвращает объект message с блоками content и usage. Текст находится в текстовых блоках; слова генерации могут отличаться. Чтобы оценить входные токены без генерации, вызовите POST /v1/messages/count_tokens с теми же model и messages; эта операция всё равно учитывается в минутном лимите запросов. Формат событий описан в [потоках](/ru/docs/api/streaming).

## Прочитайте ответ и usage

Пример показывает форму завершённого ответа; ID, текст и токены вашего запроса будут другими:

~~~json
{
  "id": "msg_018f3f407b447cc4b8ba3f62656c299c",
  "type": "message",
  "role": "assistant",
  "model": "gpt-5.6-sol",
  "content": [{ "type": "text", "text": "Готово." }],
  "stop_reason": "end_turn",
  "stop_sequence": null,
  "usage": {
    "input_tokens": 12,
    "cache_creation_input_tokens": 0,
    "cache_read_input_tokens": 0,
    "output_tokens": 5
  }
}
~~~

Показывайте пользователю текстовые блоки `content`, а `tool_use` выполняйте отдельным циклом только после проверки входных аргументов. `stop_reason: max_tokens` означает частичный ответ; `tool_use` означает, что ход ждёт результат инструмента. В Messages `input_tokens` обозначает некэшированную часть ввода: при анализе контекста учитывайте также cache read/write. Окончательное списание в кредитах смотрите в [активности API](/ru/docs/account/usage).

## Передавайте блоки потоком

Ключ `-N` позволяет видеть нативные события Messages по мере поступления. Один раз создайте ключ идемпотентности, чтобы после обрыва повторить тот же логический запрос:

~~~bash
export UNLIMGPT_REQUEST_KEY="$(openssl rand -hex 16)"
~~~

Отправьте запрос из той же оболочки:

::code-group
#curl
~~~bash
test -n "${UNLIMGPT_REQUEST_KEY:-}" \
  && printf 'x-api-key: %s\n' "$API_KEY" \
  | curl -q -H @- -i -N "$BASE_URL/v1/messages" \
    -H "anthropic-version: 2023-06-01" \
    -H "Content-Type: application/json" \
    -H "Idempotency-Key: $UNLIMGPT_REQUEST_KEY" \
    -d '{
  "model": "gpt-5.6-sol",
  "max_tokens": 64,
  "messages": [
    {
      "role": "user",
      "content": "Посчитай до трёх."
    }
  ],
  "stream": true
}'
~~~

::

HTTP 200 означает начало потока. `message_start` содержит ID сообщения; `content_block_start`, `content_block_delta` и `content_block_stop` обозначают границы каждого текстового блока или вызова инструмента. Прочитайте итоговые `stop_reason` и `usage` в `message_delta`, затем дождитесь `message_stop`, прежде чем отмечать запрос завершённым. Событие `event: error` в середине потока или обрыв до `message_stop` не означает успешный ответ. Для повтора запускайте только второй блок с прежним ключом и неизменным телом; новый ключ может начать ещё одну платную генерацию. В [руководстве по потокам](/ru/docs/api/streaming) описаны восстановление и различия протоколов.
