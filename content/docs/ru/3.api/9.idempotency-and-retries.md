Задайте `BASE_URL` как корневой HTTPS-адрес API без завершающего `/` и без `/v1`, а `API_KEY` передайте из хранилища секретов. OpenAI-совместимые SDK используют `${BASE_URL}/v1`, Anthropic-совместимые — `BASE_URL`.

Передавайте `Idempotency-Key`, если приложение может повторить запрос генерации после таймаута или потери соединения. Для каждого нового логического запроса создавайте новое непредсказуемое значение и храните его вместе с точными параметрами. При каждом повторе используйте **то же значение и те же параметры**. В течение 24 часов завершённый дубликат возвращает итог без новой генерации и списания. Новому запросу пользователя нужен новый ключ, даже если текст совпал.

## Отправьте и сохраните логический запрос

Передайте процессу `API_KEY`. В оболочке с OpenSSL один раз создайте случайный ключ; в приложении используйте свой криптографически стойкий генератор UUID или эквивалент. Храните значение идемпотентности и тело запроса в состоянии приложения до терминального исхода. Не помещайте API-ключ или prompt в значение идемпотентности.

~~~bash
export UNLIMGPT_REQUEST_KEY="$(openssl rand -hex 16)"
~~~

В той же оболочке отправьте запрос. Если генерация ключа не удалась, проверка остановит запрос до платной работы:

::code-group
#curl
~~~bash
test -n "${UNLIMGPT_REQUEST_KEY:-}" \
  && printf 'Authorization: Bearer %s\n' "$API_KEY" \
  | curl -q -H @- -i "$BASE_URL/v1/responses" \
    -H "Content-Type: application/json" \
    -H "Idempotency-Key: $UNLIMGPT_REQUEST_KEY" \
    -d '{
  "model": "gpt-5.6-sol",
  "input": "Поздоровайся.",
  "max_output_tokens": 64,
  "stream": false
}'
~~~

#python
~~~python
import json
import os
import urllib.request


class NoRedirect(urllib.request.HTTPRedirectHandler):
    def redirect_request(self, request, fp, code, msg, headers, newurl):
        return None


opener = urllib.request.build_opener(NoRedirect)

base_url = os.environ["BASE_URL"]
key = os.environ["API_KEY"]
request_key = os.environ["UNLIMGPT_REQUEST_KEY"]

request = urllib.request.Request(
    base_url + "/v1/responses",
    headers={
        "Authorization": f"Bearer {key}",
        "Content-Type": "application/json",
        "Idempotency-Key": request_key,
    },
    data=json.dumps(
        {
            "model": "gpt-5.6-sol",
            "input": "Поздоровайся.",
            "max_output_tokens": 64,
            "stream": False,
        }
    ).encode("utf-8"),
)

with opener.open(request, timeout=120) as response:
    print(response.status, response.headers.get("request-id"))
    print(response.read().decode("utf-8"))
~~~
#go
~~~go
package main

import (
	"fmt"
	"io"
	"net/http"
	"os"
	"strings"
	"time"
)

func main() {
	client := &http.Client{
		Timeout: 120 * time.Second,
		CheckRedirect: func(*http.Request, []*http.Request) error {
			return http.ErrUseLastResponse
		},
	}
	baseURL := os.Getenv("BASE_URL")
	if baseURL == "" {
		panic("BASE_URL is required")
	}
	key := os.Getenv("API_KEY")
	if key == "" {
		panic("API_KEY is required")
	}
	requestKey := os.Getenv("UNLIMGPT_REQUEST_KEY")
	if requestKey == "" {
		panic("UNLIMGPT_REQUEST_KEY is required")
	}

	req, err := http.NewRequest(
		"POST",
		baseURL+"/v1/responses",
		strings.NewReader(`{
  "model": "gpt-5.6-sol",
  "input": "Поздоровайся.",
  "max_output_tokens": 64,
  "stream": false
}`),
	)
	if err != nil {
		panic(err)
	}
	req.Header.Set("Authorization", "Bearer "+key)
	req.Header.Set("Content-Type", "application/json")
	req.Header.Set("Idempotency-Key", requestKey)

	response, err := client.Do(req)
	if err != nil {
		panic(err)
	}

	fmt.Println(response.StatusCode, response.Header.Get("request-id"))
	if _, err := io.Copy(os.Stdout, response.Body); err != nil {
		panic(err)
	}
	response.Body.Close()
}
~~~
::

При успехе ожидайте терминальный JSON-ответ. Сохраните HTTP-заголовок `request-id` для диагностики; он отличается от ID запуска в [активности API](/ru/api-activity). Для повтора запускайте **только второй блок** с тем же значением переменной и неизменным телом. Повторное выполнение команды OpenSSL создаст новый ключ и может начать вторую платную генерацию.

## Решите, можно ли повторять

- Дубликат во время первого исполнения получает временный HTTP 409 с `retry-after: 1` и `x-should-retry: true`. Подождите не меньше указанного времени и отправьте неизменный запрос с тем же ключом.
- Тот же ключ с другими параметрами даёт постоянный 409 и `x-should-retry: false`. Это ошибка приложения; новый ключ создавайте только для действительно нового логического запроса.
- При HTTP 429 читайте `retry-after` и `x-should-retry`. Временный лимит частоты допускает повтор после паузы; лимит пакета требует обновления окна или тарифа. Не запускайте цикл повторов при `x-should-retry: false`.
- После обрыва потока проверьте активность и последнее нативное событие. Поток может сообщить ошибку после HTTP 200; для безопасного повтора используйте тот же ключ, если клиент поддерживает такое поведение.

Ограничивайте число повторов и общее время ожидания на своей стороне. Не повторяйте автоматически неповторяемую публичную ошибку и не меняйте тело, сохраняя старый ключ. См. [потоки](/ru/docs/api/streaming), [ошибки и лимиты](/ru/docs/api/errors-and-limits) и контекст протокола в [Responses](/ru/docs/api/responses).
