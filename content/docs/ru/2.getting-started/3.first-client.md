Выберите клиент в [матрице совместимости](/ru/docs/reference/clients). Нужны доступ к API в выбранной организации, кредиты для итогового запроса и разблокированное системное хранилище секретов. Установите выпуск [UnlimGPT CLI](/ru/docs/cli/install), в справке которого есть `configure`, затем проверьте:

~~~text
unlimgpt --version
unlimgpt --help
unlimgpt clients
~~~

Список клиентов показывает автоматический, безопасный через запуск и ручной режимы. Ниже Codex служит примером автоматической настройки. Для другого клиента сначала откройте его [отдельное руководство](/ru/docs/reference/clients).

## Просмотрите и примените настройку Codex

Просмотрите изменения конфигурации без входа, создания ключа и записи файлов:

~~~text
unlimgpt configure codex --dry-run
~~~

Проверьте путь файла и предлагаемую правку. Перед применением полностью завершите Codex Desktop: закрытие окна может оставить процесс работающим. Если у вас есть старые чаты Codex, CLI перед переключением активного provider создаст резервную копию хранилищ сеансов. Она содержит переписку, поэтому защищайте её как личные чаты. Затем выполните:

~~~text
unlimgpt configure codex
~~~

CLI попросит подтвердить изменения. При необходимости команда откроет вход в браузере, создаст ключ для выбранного профиля и сохранит секрет в системном хранилище. При успешной автоматической настройке она напечатает подтверждение и команду `Undo:` для каждой правки файла. Сохраните эти receipts для [безопасного отката](/ru/docs/cli/configure); откат не отзывает API-ключ.

## Проверьте аккаунт, ключ и клиент

~~~text
unlimgpt whoami --json
unlimgpt models
~~~

JSON-ответ показывает аккаунт и организацию OAuth-входа CLI. Сверьте `data.organization.id` с организацией, выбранной в браузере. Список моделей проверяет **сохранённый API-ключ** без платной генерации. Команды используют разные credentials: успешное чтение моделей само по себе не доказывает, что ключ принадлежит организации из `whoami`.

Если настройка напечатала ID нового API-ключа, убедитесь, что этот ID есть в `unlimgpt keys list` выбранной организации. Если в профиле уже был ключ и вы переключили организацию, остановитесь до платного запроса. Выполните `unlimgpt keys create --name codex-current-org` после входа в нужную организацию: команда выберет новый ключ для профиля. Полностью закройте Codex Desktop, повторите `unlimgpt configure codex`, затем снова выполните проверки. Старый ключ отдельно проверьте в его исходной организации. Если неверна сама OAuth-организация, [исправьте авторизацию CLI](/ru/docs/getting-started/login).

Выберите из `unlimgpt models` канонический ID модели, а не её отображаемое имя. Если настроенной модели нет в списке, закройте Codex Desktop и повторите `configure` с `--model`, указав ID из каталога. Например, используйте `unlimgpt configure codex --model gpt-5.6-sol` **только если** в каталоге есть `gpt-5.6-sol`. Перед открытием Codex сохраните новую команду `Undo:`, если она появилась.

Снова откройте Codex Desktop, убедитесь, что прежние чаты видны, затем создайте новый чат и попросите короткий ответ от [доступной модели](/ru/docs/api/models). Дождитесь непустого ответа; его текст может отличаться, запрос может списать кредиты. Найдите операцию по endpoint, времени и исходу в [активности API](/ru/api-activity). Если клиент не подключился, пройдите [инструкцию Codex](/ru/docs/clients/codex), затем используйте [doctor](/ru/docs/troubleshooting/doctor) для диагностики. Doctor не заменяет проверку реального запроса.

Claude Code тоже поддерживает автоматическую настройку. Continue CLI использует безопасный запуск, а Cursor, Cline и Roo требуют ручных шагов в собственных настройках. В ручном режиме `configure` прямо сообщает, что клиент ещё не настроен, и выдаёт следующие действия; ключ в буфере обмена остаётся секретом. Откройте [руководство своего клиента](/ru/docs/reference/clients) и проверьте там реальный запрос. Перед повтором неудачной настройки посмотрите её вывод и [API-ключи](/ru/api-keys): ключ или receipt могли уже появиться.
