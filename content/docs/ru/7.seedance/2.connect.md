Задайте `BASE_URL` как корневой HTTPS-адрес, выданный вместе с вашим API-ключом, без пути и завершающего слэша. Если выданный адрес заканчивается на `/v1`, уберите этот суффикс. URL создания — `$BASE_URL/v1/videos`. Храните API-ключ на сервере. Передавайте `Authorization: Bearer <API_KEY>` только этому API origin при создании, чтении задачи и скачивании через API.

Пароль кабинета отличается от API-ключа. Проверьте разрешённые модели, группу, срок действия, квоту и IP-ограничения ключа в кабинете или у поддержки. Наличие модели или расширенного поля в справочнике не доказывает доступ для любого ключа.

## Настройка терминала

Примеры используют Bash, curl и jq. На macOS сначала запустите `bash`. Введите корневой адрес, затем ключ без вывода на экран и записи в историю команд:

```bash
printf 'Базовый URL API: '
read -r BASE_URL
export BASE_URL
printf 'Ключ API: '
read -rs API_KEY
printf '\n'
export API_KEY
```

Проверьте, что `BASE_URL` начинается с `https://` и не содержит путь, query или встроенные credentials. Удаляйте ключи, cookies, содержимое запроса и подписанные media URLs из журналов и скриншотов для поддержки.

## Проверка доступа

До создания потенциально платной задачи убедитесь, что ID модели из [Параметров](/ru/docs/seedance/parameters) доступен ключу. Если самостоятельно создать API-ключ нельзя, обратитесь в поддержку.
