Seedance uses a client contract compatible with the Videos modality: `POST /v1/videos` with `model`, `prompt`, `seconds` and `size`. The [official OpenAI Videos API](https://developers.openai.com/api/docs/deprecations#2026-03-24-sora-2-video-generation-models-and-videos-api) ceased operation on September 24, 2026; the [Videos reference](https://developers.openai.com/api/reference/resources/videos) is a historical request format guide, while Seedance continues to use `/v1/videos` as documented here. Model and reference availability depends on your connection and API key. An accepted request returns a task ID; it does not mean the video is ready.

## Quick start

Set `BASE_URL` and `API_KEY` as in [Connect](/docs/seedance/connect). Save this as `request.json`:

```json
{
  "model": "seedance-2.5",
  "size": "1280x720",
  "prompt": "A paper boat glides across a quiet lake at sunrise, one continuous shot.",
  "seconds": "5"
}
```

Create once and save `id`:

```bash
curl --fail --silent --show-error --max-time 120 "$BASE_URL/v1/videos" -H "Authorization: Bearer $API_KEY" -H 'Content-Type: application/json' --data-binary @request.json -o created.json
jq -r '.id' created.json
```

Read `GET /v1/videos/{id}` until `completed` or `failed`. On success, download through `/v1/videos/{id}/content` with your API key, or use an optional signed `content.video_url` without your API key; see [Results](/docs/seedance/results). Save the ID before continuing so a restart does not create another paid task.

## Operations

| Purpose | Method and path | Authentication |
|---|---|---|
| Create a Seedance task | `POST /v1/videos` | API Bearer |
| Read the same task | `GET /v1/videos/{id}` | API Bearer |
| Download video | `GET /v1/videos/{id}/content` | API Bearer |
| Download a signed URL | GET the exact HTTPS URL in `content` or `Location` | No API Bearer |

Task retrieval uses `queued`, `in_progress`, `completed`, `failed`. Unknown statuses are not success.
