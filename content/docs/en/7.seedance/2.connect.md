Set `BASE_URL` to the root HTTPS origin supplied with your API key, without a path or trailing slash. If the supplied address ends in `/v1`, remove that suffix. The create URL is `$BASE_URL/v1/videos`. Keep the API key on your server. Send `Authorization: Bearer <API_KEY>` only to that API origin for creation, task reads and API downloads.

The console password is distinct from the API key. Check the key's allowed models, group, expiry, quota and any IP restrictions in the console or with support. A listed model or advanced field does not establish access for every key.

## Terminal setup

These examples use Bash, curl and jq. On macOS run `bash` first. Enter the root address, then enter the key without echoing it or adding it to shell history:

```bash
printf 'API base URL: '
read -r BASE_URL
export BASE_URL
printf 'API key: '
read -rs API_KEY
printf '\n'
export API_KEY
```

Validate that `BASE_URL` begins with `https://` and has no path, query or embedded credentials. Remove keys, cookies, request content and signed media URLs from logs and support screenshots.

## Access check

Confirm the model ID in [Parameters](/docs/seedance/parameters) is available for the key before creating a potentially billable task. If key creation is unavailable, ask support for an API key.
