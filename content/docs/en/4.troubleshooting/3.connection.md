Set `BASE_URL` to your HTTPS API origin without a trailing slash or `/v1`, and pass `API_KEY` from your credential store. OpenAI-compatible SDKs use `${BASE_URL}/v1`; Anthropic-compatible SDKs use `BASE_URL`.

Use the exact public origin for the chosen protocol: `${BASE_URL}/v1` for an OpenAI-compatible client; `BASE_URL` for an Anthropic-compatible client. Do not copy a URL that contains a key. Check the network before generation: reading the model catalog does not debit credits.

## Free checks first

1. Send `GET /healthz` to `BASE_URL`. A response with status `ok` confirms that the HTTP service is reachable. Check access to a specific model separately.
2. Check that the client uses HTTPS and the right base URL. The Messages endpoint itself is /v1/messages even though its base URL has no /v1.
3. Use [GET /v1/models](/docs/api/models) with the key to separate network, authentication and catalog problems.
4. If a client fails while curl succeeds, compare its configured protocol, model ID and credential source with [client compatibility](/docs/reference/clients).
5. Run [doctor](/docs/troubleshooting/doctor) for free client checks. Only an explicit --probe --yes can make a paid inference check.

#python
~~~python
import os
import urllib.request


class NoRedirect(urllib.request.HTTPRedirectHandler):
    def redirect_request(self, request, fp, code, msg, headers, newurl):
        return None


opener = urllib.request.build_opener(NoRedirect)

base_url = os.environ["BASE_URL"]
key = os.environ["API_KEY"]

request = urllib.request.Request(
    base_url + "/healthz",
    headers={},
)

with opener.open(request, timeout=10) as response:
    print(response.status, response.headers.get("request-id"))
    print(response.read().decode("utf-8"))

request = urllib.request.Request(
    base_url + "/v1/models",
    headers={"Authorization": f"Bearer {key}"},
)

with opener.open(request, timeout=10) as response:
    print(response.status, response.headers.get("request-id"))
    print(response.read().decode("utf-8"))
~~~
#go
~~~go
package main

import (
	"fmt"
	"io"
	"net/http"
	"os"
	"time"
)

func main() {
	client := &http.Client{
		Timeout: 10 * time.Second,
		CheckRedirect: func(*http.Request, []*http.Request) error {
			return http.ErrUseLastResponse
		},
	}
	baseURL := os.Getenv("BASE_URL")
	if baseURL == "" {
		panic("BASE_URL is required")
	}
	key := os.Getenv("API_KEY")
	if key == "" {
		panic("API_KEY is required")
	}

	req, err := http.NewRequest("GET", baseURL+"/healthz", nil)
	if err != nil {
		panic(err)
	}

	response, err := client.Do(req)
	if err != nil {
		panic(err)
	}

	fmt.Println(response.StatusCode, response.Header.Get("request-id"))
	if _, err := io.Copy(os.Stdout, response.Body); err != nil {
		panic(err)
	}
	response.Body.Close()
	req, err = http.NewRequest("GET", baseURL+"/v1/models", nil)
	if err != nil {
		panic(err)
	}
	req.Header.Set("Authorization", "Bearer "+key)
	response, err = client.Do(req)
	if err != nil {
		panic(err)
	}

	fmt.Println(response.StatusCode, response.Header.Get("request-id"))
	if _, err := io.Copy(os.Stdout, response.Body); err != nil {
		panic(err)
	}
	response.Body.Close()
}
~~~
::

The first command should return HTTP 200 and `{"status":"ok"}`. This confirms that the public service responds; it does not verify your key, model availability or a generation request. The second checks HTTPS, your key, and catalog access together. HTTP 200 with `data` confirms the service can use the key; 401 or 403 leads to [authentication](/docs/api/authentication), while 404 for a particular model ID leads to [the catalog](/docs/api/models). Neither free check proves that a paid model request will succeed. Do not put a secret-expanded command in a report or screenshot.

| Observation | Next check |
| --- | --- |
| DNS fails or no connection opens | Check DNS, proxy settings, and outbound HTTPS access to the public hostname. Keep the time and secret-free client error. |
| TLS validation fails | Check the device clock and trusted certificate store, including a managed proxy. Do not disable certificate verification. |
| `/healthz` works but the catalog returns 401/403 | Check the Bearer header, key expiry, organization, and permissions. A new paid generation will not fix authentication. |
| The catalog works but the AI client does not | Compare base URL, protocol, canonical model ID, and credential delivery with [client compatibility](/docs/reference/clients). |
| The API responds but a stream disconnects | Read the last SSE event and check the client's timeout. Keep the same idempotency key until you decide whether to retry. |

If DNS or TLS fails, do not disable certificate validation to proceed. Report the public hostname, time, safe error code and request ID if one exists. For a request that reached the API but failed, see [error recovery](/docs/troubleshooting/errors).
